\begin{abstract}
OpenAPI contracts describe expected inputs and responses for REST APIs,
serving as a partial oracle for testing without code access. Contract-guided
\textit{fuzzing} produces repeated findings of unequal importance. Regression
test prioritization orders test cases before execution; here, findings are
ordered afterward. This work evaluates the contributions and limitations of grouping
and prioritizing these findings using \textit{fuzzy} logic. The OpenAPI
Contract Fuzzer generates and modifies requests, compares responses with the
contract, and groups equivalent responses. A Mamdani system calculates
priorities through \textit{fuzzy} inference and records rules and decisions.
The model was revised using four APIs and tested, with its rules and
parameters fixed, on a fifth, Meilisearch. Priorities were compared with a
reference produced blindly by three instances of the GPT-5.6 Luna language
model. Initially, the model repeated the priority indicated by HTTP status.
The revised model considers context, since accepting an input that should be
rejected requires different attention from rejecting it. On Meilisearch, it
assigned the same priority band as the reference to 120 of 122 groups of
similar findings. A rule that considers only the status matched it in 4.
\end{abstract}

\keywords{REST APIs, OpenAPI, Fuzzing, Contract Testing, Fuzzy Logic.}
     
\begin{resumo}
\looseness=-1
Contratos OpenAPI descrevem entradas e respostas esperadas de APIs REST,
servindo como oráculo parcial para testes sem acesso ao código. O
\textit{fuzzing} guiado por contrato produz achados repetidos e de
importância desigual. Na priorização de testes de regressão, ordenam-se
casos antes da execução; aqui, ordenam-se achados depois dela. Este trabalho
avalia as contribuições e limitações de agrupar e priorizar esses achados por lógica \textit{fuzzy}. O OpenAPI
Contract Fuzzer gera e altera requisições, compara respostas com o contrato
e agrupa respostas equivalentes. Um sistema Mamdani calcula prioridades por
inferência \textit{fuzzy} e registra regras e decisões. O modelo foi
revisado com quatro APIs e testado, com regras e parâmetros fixados, em uma
quinta, o Meilisearch. As prioridades foram comparadas com uma referência
produzida às cegas por três instâncias do modelo de linguagem GPT-5.6 Luna.
Inicialmente, o modelo repetia a prioridade indicada pelo status HTTP. O
modelo revisado considera o contexto, pois aceitar uma entrada que deveria
ser rejeitada exige atenção diferente de rejeitá-la. No Meilisearch, ele
atribuiu a mesma faixa de prioridade que a referência a 120 de 122 grupos
de achados semelhantes. Uma regra que considera apenas o status coincidiu
em 4.
\end{resumo}
